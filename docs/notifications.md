# Notifications

The **Inbox** tab is the app's attention view. Its sidebar label and the status-bar bell shortcut carry a badge while items need attention; clicking either opens `/inbox`.

Items are derived live rather than stored separately: pending tool approvals ([which tools need one](/roles-capabilities-skills#tool-approvals)), latest failed runs, blocked or watchdog-tripped bots, an armed spend circuit breaker ([what the breaker does](/bots#lifecycle)), and unread notifications. A bot waiting on an approval shows that row ahead of its older run failure. A notification linked to one of those conditions does not appear twice. Rows are newest first with a kind icon, bot name where applicable, a one-line detail, and relative time. Clicking routes run problems to that bot's chat with Logs expanded and breaker alerts to Settings → System.

Approval rows show the tool name and its argument summary with **Approve** and **Deny** right on the row, so a waiting bot can be released without opening its chat; deciding removes the row, and a decision made from the chat sidebar removes it here too. Unread rows can be marked individually or with **Mark all read**; reading removes the linked notification row. Other items clear when their source resolves — for example, after a new successful run, once a blocked state clears, or when the spend cap is raised or cleared. There is no arbitrary dismiss: an item that would immediately reappear stays put. When nothing remains, Inbox reads **All clear** and remembers this browser's last resolved time. The action row filters items by kind and bot.

## Sounds

Settings → **General** → **Notification sounds** (off by default) plays a short chime when a new notification arrives while any app page is open; a Preview button lets you hear it before enabling. A bot can pick its own sound — none, the default chime, or one of six built-in synth sounds — in the bot's General tab; bots without a pick follow the global default. Sounds are bundled with the app and obey browser autoplay rules: the first sound plays after any interaction on the page.

## Browser push

On first sign-in, the app asks once for browser notification permission and subscribes this device automatically (works in supported browsers, including when the site is installed as a [PWA](/pwa)). Dismissing the prompt does not nag on later visits; change the browser's site permission manually to opt back in. Settings → **General** → **Browser push** shows exactly one state and recovery control — **Unsubscribe** while subscribed, or **Retry** after a failed registration — never both. Outdated client subscriptions are removed automatically before retrying; choosing Retry may request permission again. Each new notification then delivers one silent system notification even when no tab is open; clicking it marks the notification read and opens its source, signing in first on a cold start. Back returns where you were. Browsers without push support simply don't show the controls — everything else keeps working.
