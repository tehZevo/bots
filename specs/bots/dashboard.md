# Bots dashboard

Single-page console for operating bots; any signed-in user may operate all bots (`../auth/multi-user.md`).

- A status bar stretches across the very top of the app, above the sidebar, showing bot totals and running counts per `status-colors.md`, refreshed by the same polling as the cards, plus the global Pause/Resume toggle (`global-pause.md`) and the `Stop all` panic button (`emergency-stop.md`).
- Bots tab (default view): a card per bot showing its name on one line — names too long for the card truncate with an ellipsis (full name available via title) — with status as a colored circle in the card's upper-right corner using the health levels of `status-colors.md`; on desktop, hovering the circle reveals its meaning. Creating a bot adds a card; selecting a card opens that bot's chat sidebar (`../chat/sidebar.md`).
- Under the bot name the card shows the assigned role in secondary styling and parentheses — e.g. `(developer)` in italic muted text on its own line, aligned with the name; bots without a role show no line at all.
- When a bot has a current task and/or status substep, the card shows them per `task-and-status.md`.
- On every main screen that uses them, filters sit beside the search field on the same row — one horizontal control bar (search first), wrapping to multiple lines only when width runs out — never stacked below it. A visible gap separates that bar from the content below it. Above the cards sit a search field (case-insensitive substring match on bot name), a status filter: one dropdown multiselect over the health levels of `status-colors.md` — `Active` / `Idle` / `Issues` / `Blocked` / `Disabled`, a role filter: one searchable dropdown multiselect listing defined roles plus a `(no role)` entry, and a tag filter: one dropdown multiselect listing defined tags (`../tags/tags.md`).
- Each dropdown's summary button carries its label — `Status:`, `Role:` or `Tag:` followed by `All` when nothing is selected and the comma-joined selection otherwise; selecting entries keeps only bots matching the chosen statuses AND the chosen roles AND the chosen tags (entries within one filter are OR-ed), and clearing every selection returns that filter to `All`. All four combine, with an empty "no matches" state. Filtering is client-side over the polled list.
- Create a bot via the "Add bot" modal on the bots tab (`create.md`).
- Detail modal contents and the logs view are specified in `detail.md`; all views refresh by polling the API.
- Works on phones and desktops: single-column layout below tablet width — navigation moves behind a hamburger menu (see `../ui/navigation.md`), modals span the screen, and controls are touch-sized. No horizontal scrolling at 360px wide.
- The server serves the built UI from its own origin; in dev Vite proxies `/api` → `:8075`.
