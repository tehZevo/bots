# Bot status line

- A bot exposes `current_task` (long-running "what I'm working on") and, beneath it, `status`: a short live substep of that task — progress ("running migration 3/5"), waiting ("rate-limited, backing off") or trouble ("API keeps rejecting my payload"). Both render on cards and in the detail header per `dashboard.md`, status italic in the muted secondary color; null until set.
- The agent gets a `set_status(text, level?)` tool — separate from `set_current_task`: status tracks fine-grained progress inside a task while the task stays stable. Setting or replacing the current task clears status to null (substeps belong to their task). Empty status text clears it.
- `level` is `"ok"` (default), `"issue"` or `"blocked"`. A non-empty status with level `issue` turns the bot's health color yellow; `blocked` — the agent itself declares it cannot proceed — turns it red (`status-colors.md`). Clearing status removes either color.
- Agent-reported `blocked` shows identically to system red but never replaces run truth: a failing latest run stays red even after the agent reports `ok`; red stays system-derived and always overrides agent-reported yellow.
- Task and status share one last-updated timestamp: any `set_current_task` or `set_status` call refreshes it (`bots/current-task.md`), and the card/detail show a single relative-age label (e.g. `5m ago`) for the pair — not separate ages per line.
- `set_status` takes no bot argument — it always targets the running bot; setting status never counts as output. `GET /api/bots` includes `status`; Clear memory resets task and status to null together (`bots/interrupt.md`).
