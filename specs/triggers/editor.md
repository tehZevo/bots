# Triggers tab layout

- The bot detail `Triggers` tab is a master/detail view: a left-hand list of the bot's triggers with a "+ Add trigger" button pinned above it; the right pane shows the selected trigger.
- List rows show the trigger's name on the top line (its schedule, webhook or continuous label when unnamed) and, on the bottom line in muted italic, its type (`Schedule` / `Webhook` / `Continuous`) plus `(paused)` when disabled; selecting a row marks it active, asks to discard first when the current editor is dirty (`../ui/unsaved-changes.md`), and changes nothing about the bot. Opening the tab selects the first trigger, or shows an empty-state with just "+ Add trigger" when there are none.
- The right pane is an editor for the selected trigger: optional name, message text, schedule (cron / `@every`) or continuous interval for their kinds, enable toggle, webhook URL and rotate secret (with its confirmation) for webhooks, and Remove at the bottom. Edits save via "Save" only — nothing mutates on typing; Save follows the dirty-state rule (`../ui/forms.md`).
- The one-time webhook secret display carries a `?` help icon; hovering or tapping it explains usage: POST the event payload to the trigger's URL with the secret as `Authorization: Bearer <secret>`.
- "+ Add trigger" opens a blank draft in the same right pane (kind picker first, labeled `Type`), with no decorative separators on the pane; when the current editor is dirty it asks to discard first (`../ui/unsaved-changes.md`). Create adds the trigger to the list and selects it; Cancel asks to discard a dirty draft and never calls the API.
- On phones the list collapses above the editor; selecting scrolls to the editor, which carries a back control to the list that follows the same dirty-leave rule.
