# Navigation

- A persistent left sidebar on desktop carries the tabs, grouped under small-caps section labels — **Operate**: `Inbox`, `Bots`, `Teams`; **Library**: `Roles`, `Skills`, `Templates`, `Projects`, `Tags`; **Admin**: `Machines`, `Integrations`, `Secrets`, `Settings` — and the main area shows the selected tab. Bot settings open as a modal over the main area (`../bots/detail.md`).
- The product wordmark — brand mark + product name, styled as a link back to Bots — is pinned at the left end of the top status bar; on mobile the hamburger leads, then the wordmark. It is text, not an image asset requiring theming.
- The sidebar and the mobile drawer hold exactly the tab list: each tab name appears there once, as a tab. Search (`search.md`) lives in the status bar — it is not a tab and never joins these lists.
- Every tab carries a meaningful icon from a free source (open-licensed set or custom inline SVG): `Bots` a robot/cube mark, `Roles` a badge/mask mark, `Integrations` a plug/puzzle mark, `Settings` an unmistakable cogwheel — a closed circular rim with evenly spaced teeth and a hollow hub; radial-spoke or asterisk-like marks do not read as gears. Expanded tabs show icon + label; the drawer shows them too.
- The single page title is the active screen's icon + tab name, rendered in the status bar beside the wordmark; main panes never render their own title row. A tab's actions stay right-aligned at the top of its pane.
- The sidebar collapses via a dedicated icon-button docked at the sidebar's inner edge — unmistakably a collapse control, not an ambiguous chevron floating in another bar; collapsed, it is a slim rail showing only each tab’s icon — no text other than tooltips — with the active one marked, and tapping any icon selects the tab or expands the labels; expanded, it shows full tab names beside their icons. The choice persists across sessions.
- Below tablet width the sidebar is replaced by a hamburger button in the top bar; tapping it opens an overlay drawer holding the same tabs, which closes on selecting a tab or tapping outside it.
- The active tab is marked with an accent-tinted background, a left accent bar and label emphasis — distinguishable from plain hover without relying on color alone; in the collapsed rail the active icon carries the same accent.
- Selecting a different tab while a saveable form is dirty asks to discard first (`unsaved-changes.md`); Keep editing leaves the current tab selected.
- Each tab owns a URL path — `/inbox`, `/bots`, `/teams`, `/roles`, `/machines`, `/integrations`, `/skills`, `/templates`, `/projects`, `/tags`, `/secrets`, `/settings`. Selecting a tab updates the browser history so back/forward walk between tabs; opening or reloading one of these paths lands directly on that tab, with `/` showing Bots. The server answers unknown non-API paths with the app shell so deep links survive reload.
