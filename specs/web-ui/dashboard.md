# Bots dashboard

Single-page console for operating bots; any client that can reach the API may operate all bots.

- A status bar stretches across the very top of the app, above the sidebar, showing the total number of bots and how many are active/running (e.g. `4 total · 1 running`), refreshed by the same polling as the cards. The current screen's title sits at the upper-left of the main pane (see `navigation.md`).
- Bots tab (default view): a card per bot showing its name with status as a colored circle in the card's upper-right corner using the health levels of `status-colors.md` — Blocked red, Issues yellow, Active green. On desktop, hovering the circle reveals its meaning (`Blocked` / `Issues` / `Active`). Creating a bot adds a card; selecting a card opens that bot's detail modal (see `bot-detail.md`).
- Under the bot name the card shows the assigned role in secondary styling and parentheses — e.g. `(developer)` in italic muted text on its own line, aligned with the name; bots without a role show no line at all.
- When a bot has a current task and/or status substep, the card shows them under the (role) line: task on its own line (`taskline`), status italic muted beneath it (`statline`), with one shared relative-age label ("· 5m ago") attached to the last rendered line — never separate ages (`bots/status-line.md`). Both truncate with ellipsis and expose full text via title.
- On every main screen that uses them, filters sit beside the search field on the same row — one horizontal control bar (search first), wrapping to multiple lines only when width runs out — never stacked below it. Above the cards sit a search field (case-insensitive substring match on bot name), a status filter: one dropdown multiselect over the health levels of `status-colors.md` — `Active` / `Idle` / `Issues` / `Blocked` / `Disabled`, and a role filter: one searchable dropdown multiselect listing defined roles plus a `(no role)` entry.
- Each dropdown's summary button carries its label — `Status:` or `Role:` followed by `All` when nothing is selected and the comma-joined selection otherwise; selecting entries keeps only bots matching the chosen statuses AND the chosen roles (entries within one filter are OR-ed), and clearing every selection returns that filter to `All`. All three combine, with an empty "no matches" state. Filtering is client-side over the polled list.
- Create a bot via the "Add bot" modal on the bots tab (see `create-bot.md`) — name, optional system prompt, optional role.
- Detail modal contents are specified in `bot-detail.md` (General / Triggers / Logs tabs).
- The logs tab shows run history (status + output/error); the view refreshes by polling the API.
- Works on phones and desktops: single-column layout below tablet width — navigation moves behind a hamburger menu (see `navigation.md`), modals span the screen, and controls are touch-sized. No horizontal scrolling at 360px wide.
- The server serves the built UI from its own origin; in dev Vite proxies `/api` → `:8787`.
